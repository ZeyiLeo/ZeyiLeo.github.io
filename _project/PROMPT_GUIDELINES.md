# Website prompt-writing preferences

Established by the owner on 2026-11-05 for this and subsequent website prompt updates.

- When the owner asks to write a prompt, deliver a finished, reusable prompt for the implementing Work chat. Do not treat a prompt-only request as authorization to implement the website.
- Write in Chinese, with the judgment of an experienced product manager: explain the user need, intended visitor experience, scope, priorities, dependencies, implementation requirements, and acceptance criteria.
- Make the prompt detailed and logically connected. Translate subjective feedback such as insufficient interactivity or sparse content into observable behavior and reviewable deliverables.
- Carry forward previous accepted decisions and protections. Identify what this iteration changes and what must remain intact.
- Inspect supplied references. Separate visible composition in a screenshot from motion observed in a video; do not invent animation timing or claim unseen effects were verified.
- For each requested animation, identify its reference, location, trigger, initial/active/final states, user action, content purpose, mobile treatment, reduced-motion treatment, and validation evidence.
- Define numerical expansion targets against a recorded baseline, explain the multiplier used, and count substantive, distinct content rather than duplicated markup, navigation, hidden copies, or padding.
- Use confirmed personal facts and existing source records. New explanatory copy and reflective writing may be drafted for local owner review; never invent autobiographical incidents, qualifications, results, past authorship, or publication history.
- Present interaction as a useful way to explore the owner's identity and work. Preserve native scrolling, keyboard/touch access, readable content, maintainability, and clear navigation.
- Preserve the confirmed original headshot and immutable original CV unless the owner explicitly changes these instructions. Old-site screenshots supply content/photo clues only, not a design system.
- Finish with concrete deliverables, appropriate validation, known limitations, and publication scope. Current website iterations remain local unless the owner authorizes release.
- Future prompts should inherit these preferences without making the owner repeat them. The latest owner instructions take precedence.
